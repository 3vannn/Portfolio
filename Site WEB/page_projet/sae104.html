SAE 1.04 — Création d'une base de données

À partir de documents d'un fournisseur énergétique, conception d'un diagramme de classe, modélisation relationnelle, écriture de scripts SQL et interrogation des données.

🎯Contexte et objectifs

La SAE 1.04 portait sur la conception et la mise en place d'une base de données relationnelle à partir d'un cahier des charges réel : des documents décrivant le système d'information d'une compagnie de fournisseur énergétique.

Le projet couvrait l'ensemble du cycle de vie d'une base de données : de la rétro-ingénierie d'un modèle existant, à la conception d'un nouveau modèle objet, jusqu'à l'implémentation SQL et l'interrogation des données.

AC 14.01 — Mettre à jour et interroger une base de données relationnelle AC 14.03 — Concevoir une base de données relationnelle à partir d'un cahier des charges

📋Étapes du projet

  • 1
    Critique et rétro-ingénierie — Analyse critique de la base de données existante, identification des problèmes de normalisation, proposition d'un nouveau modèle corrigé (diagramme de classe) et script SQL.
  • 2
    Requêtes SQL — Réponse aux différentes requêtes imposées : projections, sélections, jointures, agrégations. Livrable sous forme de script SQL.
  • 3
    Extension de la base — Proposition d'une extension (diagramme de classe + implémentation SQL) avec un jeu de données test pour peupler la nouvelle base.

🔧Ce qui a été réalisé

  • Rétro-ingénierie : passage du modèle relationnel existant au modèle conceptuel (diagramme de classe)
  • Critique de la modélisation existante et identification des anomalies
  • Proposition d'un modèle corrigé avec normalisation
  • Implémentation des contraintes SQL (clés primaires, étrangères, domaines)
  • Écriture de requêtes SQL complexes (jointures multiples, agrégations, sous-requêtes)
  • Extension de la base avec une nouvelle fonctionnalité + jeu de données test
